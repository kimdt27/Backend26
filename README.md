# Backend Development – PBA Web 🚀

Welcome to **Backend Development**!

This repository is for **1st semester students on the PBA in Web Development**.

During the semester, this repository will contain the code examples, exercises, experiments, and other materials we use in class.

## 👋 Welcome

In this course, we are going to work with the part of web development that happens **behind the frontend**.

We will mainly use **PHP and MySQL** to explore how backend applications work — from receiving data from a browser to storing it in a database, handling users, and building more structured and secure applications.

Some of the code will be simple. Some of it will get messy. Some of it will probably break.

That's part of the process. 🙂

## 🧰 What we will work with

During the semester, we will cover topics such as:

* **PHP fundamentals**
* **Forms and user input**
* **File and image uploads**
* **MySQL databases**
* **CRUD** – Create, Read, Update and Delete
* **Database connections**
* **MySQLi and PDO**
* **Login systems and sessions**
* **Password hashing and encryption**
* **Object-Oriented Programming (OOP)**
* **Classes, inheritance, interfaces and abstract classes**
* **Basic design patterns**
* **Routing and application structure**
* **Web security**
* **XSS and CSRF**

The examples in this repository will grow during the semester as we introduce new concepts.

## 📁 Repository structure

You will find different folders containing examples from class.

Some folders contain small isolated examples, while others contain larger examples that combine several concepts.

The `inclass` folders contain code created or used during class and may therefore sometimes be a little experimental.

**Don't expect everything in here to be production-ready code.**

The purpose is to learn, experiment, and understand what is happening.

## 💻 Getting started

Clone the repository:

```bash
git clone https://github.com/kimdt27/Backend26.git
```

To get the newest examples and changes later:

```bash
git pull
```

I recommend that you keep your own experiments and exercises separate from this repository. That makes it easier to pull new examples without conflicts.

## 🧪 Learn by breaking things

You are encouraged to modify the examples.

Change things. Add things. Delete things.

See what happens.

And when something breaks:

1. Read the error message.
2. Find the line where the error occurs.
3. Try to understand why.
4. Search the documentation.
5. Ask your classmates.
6. Ask me.
7. Fix it and break something new.

Debugging isn't something that happens when programming goes wrong.

**Debugging is programming.**

## 🤖 Using AI

You are welcome to use AI tools while working with the examples and exercises.

AI can be very useful for:

* Explaining code
* Understanding error messages
* Debugging
* Exploring alternative solutions
* Generating small examples
* Asking questions you might otherwise Google

But there is one important rule:

> **If you can't explain what the code does, you're not done yet.**

Don't just ask AI to build the entire solution for you.

Use it as a tool to help you **understand and build the solution yourself**.

## 🎯 The goal

The goal of this course is not simply to learn PHP syntax.

By the end of the semester, you should have a better understanding of how web applications work behind the scenes:

**Browser → Request → Backend → Database → Backend → Response → Browser**

Once you understand that flow, moving on to other backend languages and frameworks becomes much easier.
